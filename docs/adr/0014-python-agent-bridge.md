# ADR 0014: Python bots behind a fenced agent bridge

Status: **Proposed**. Part of [#254](https://github.com/relaishq/relais/issues/254); aligned with [#255](https://github.com/relaishq/relais/issues/255). Baseline: `7cc1e2f`.

## Owner summary

**Who this is for — owner decided, 2026-10-23:** indie and startup teams self-hosting Pipecat first; LiveKit/Daily teams later.

Keep WebRTC in Relais. A Python bot changes its transport, installs a checkpoint helper, and runs in a warm pool. Killing or replacing the bot leaves the caller connected. A replacement restores bounded conversation text from the last checkpoint. Worker moves preserve the existing media guarantees; the bot reconnects without restarting.

The owning worker issues and verifies attach tokens and chooses replacement bots. Neither established media nor bot replacement needs control. Worker moves and crash takeovers still need control today; this proposal does not claim #255's future control-independent recovery.

This is a design, not measured performance. Dated owner decisions are settled; remaining recommendations need owner approval before implementation. Conversation survival covers checkpointed messages, not arbitrary Python objects, unfinished speech, provider streams, or exactly-once tool execution.

## Seven decisions and recommendations

| #254 question | Recommendation and main tradeoff |
| --- | --- |
| 1. WebSocket or gRPC? | Private WebSocket: binary Opus and JSON control. Simple Python integration; we must specify bounds, framing and version negotiation ourselves. |
| 2. Dispatch and registry? | **Owner decided, 2026-10-23:** warm pool per worker or relay. Recommend per-worker warm processes, registered directly with workers. Each worker keeps bounded local availability; runners reserve their own capacity across workers. No per-call process spawn or control-only registry. More warm memory and duplicate availability observations; atomic reservations prevent double assignment. |
| 3. History and defaults? | Require `-agent-split-checkpoints` for bridge calls: 3,072 B working, 8,192 B history. Keep the last four exchanges plus a bounded summary; fit actual UTF-8 bytes. Do not increase ceilings or change global defaults. Limited memory buys bounded storage cost. **Owner call:** approve this retained-context policy. |
| 4. Connection destination? | Connect directly to the owner. Configure bootstrap workers and a static worker-leg-to-HTTPS directory; any bootstrap worker resolves ownership through `sessionstore.Store.Get`. No relay proxy or control lookup. Operators must expose private worker endpoints and keep the directory current. |
| 5. Token issuer? | **Owner decided, 2026-10-23:** the session's owning worker issues and verifies tokens bound to session, epoch and bot instance, including after transfer. Signal/control never mint or verify tokens. This replaces the issue sketch and its two suggested issuers; worker credentials and attach fencing become explicit responsibilities. |
| 6. Python home and versions? | **Owner decided, 2026-10-23:** `python/relais-agent` and `python/pipecat-relais` live here on the same version line as Relais. One release tag versions Go binaries and both Python packages together. PyPI names: `relais-agent`, `pipecat-relais` (`relais` is taken). Costs coordinated releases and cross-language CI. **Owner call:** initially support one exact conformance-tested Pipecat/PyAV pair; widen through a tested matrix. No supported range is claimed yet. |
| 7. Public takeover target? | **Owner call:** retain local p95 <1 s for kill-to-attached on socket close, with warm capacity and reachable owner/store. For hangs, propose p95 ≤3 s from last application pong to attached, with a 2 s timeout. Separately report first-audio delay. A single <1 s claim would hide detection time. |

The release workflow builds and publishes both Python packages and Go binaries from the same tag, retaining shared fixtures and Apache-2.0 licensing. Include the bridge protocol version in [#252's compatibility manifest](https://github.com/relaishq/relais/issues/252), alongside supported tagged Go/Python pairs. CI must detect protocol-version drift; upgrade/rollback preflight must refuse incompatible pairs. Shared version numbers alone do not prove wire or checkpoint compatibility.

## Actor and media contract

Register built-in `bridge` through `pkg/workerapp`. Keep `Agent.Handle/Save/Restore`, deadlines, rollback, task classes and existing agents unchanged. Amend ADR 0010 A's compile-time-only deployment boundary and its Deferred streaming-input/PCM boundary **only for this built-in bridge**. The literal “no runtime plugin or subprocess interface” is in README; replace that limit only when shipping. Arbitrary runtime Go plugins and subprocess supervision remain excluded.

`Handle(AudioInput)` stages owned packets in a bounded outbox without waiting. Publish that outbox only after the accepted-event module accepts state/progress; rolled-back callbacks must not leak packets to Python. Full queues count an explicit input gap and notify the bot. Slow sockets never block callbacks or UDP. Network readers submit bounded task messages; they never mutate actor state in the background. `Save` returns the actor's cached bot checkpoint; it does no socket I/O. `Restore` validates cached bytes without contacting Python.

Use cancellable, per-turn streaming tasks, not an immortal task tagged with an obsolete turn. Task messages publish immutable Opus batches; `Effects.Audio` references those exact messages. Interruption advances `CancelBefore` and `ClearAudioBefore`; late attempts/attachments cannot publish. `Resumed` starts no tasks: restored tasks follow existing rules; a later timer/event can start replacement work. Planned export preserves accepted audio/backlog and resumes task cursors. Never regenerate different packets under an old reference.

**First measurement, before bridge implementation:** send 50 twenty-millisecond packets/s through real task emission, accepted-event admission and paced playback, with concurrent input and full-size checkpoints. `acceptEmission` currently spaces emissions by 100 ms. Compare five-packet batches against a prototype host-side streaming-output effect; 50 individual emits/s cannot work unchanged. Record callback/Save CPU and p99 wall time, queue growth, added latency, checkpoint age/bytes and caller gaps, locally and under race on a free runner. Retain batching if it meets existing gates and an explicitly approved latency budget. Otherwise bring the additive effect design back for approval; do not silently relax task spacing or the 100 ms callback budget.

Python converts Opus to PCM input frames and PCM output to 20 ms Opus using pinned PyAV wheels. Go remains `CGO_ENABLED=0`. Codec state resets after bot replacement; no bit-exact codec continuation claim. `RelaisTransport`, a context processor and runner/SIGTERM setup preserve the existing VAD/STT/LLM/TTS pipeline. Nonstandard context objects need an explicit serializer; DataChannel/RTVI, video and arbitrary tool-state migration are excluded.

## Attach authority and recovery

Authenticate registry, lookup and attach requests with operator-provisioned bot credentials over TLS (loopback plaintext only for local tests). Reject browser Origins, untrusted redirects and oversized requests; never put credentials in URLs/logs. Use a short-lived opaque random token, stored and verified by the issuing worker, bound to session, owner epoch, bot instance, attachment generation, expiry and protocol. Consume it once under the session fence. New assignments increment the local generation and revoke old sockets/tokens. Refresh tokens for reconnects; never accept a predecessor's token on the successor.

Only an active session can issue/accept tokens. Export/fencing closes admission before transfer. Preserve ADR 0008 during transient store failure: no per-packet or per-reattach store dependency is added to an already-live tenure. A worker under partition can have stale local knowledge; higher-epoch store ownership and the relay's old-leg fence remain authoritative. A bot token grants no ownership, checkpoint write authority or permission to undo a transfer.

Runners register with multiple configured workers and accept one capacity reservation atomically. Reservations expire; stale availability never grants attachment. Registration loss leaves attached bots running; bounded retries seek capacity without holding media/state locks. No warm bot means continued consent and silence, plus `no_capacity`, not a fabricated success or hang-up. Optional registration advertisements, telemetry and extensions time out independently; none gates media, Save or checkpoint writes. The required store retains ADR 0008 fencing and outage limits.

| Event | State and attachment rule |
| --- | --- |
| Bot socket closes / kill | Revoke attachment; keep caller transport/consent. Attach a warm replacement to the last successfully checkpointed bot pair. Clear uncertain speech; report `OutcomeUnknown`. Measure kill-to-close, close-to-attached and kill-to-attached separately. |
| Bot hangs | Application ping every 500 ms; a matching application pong must advance within 2 s. WebSocket library pong alone cannot prove pipeline liveness. Revoke before replacement. Measure last-pong-to-timeout and timeout-to-attached separately; this path cannot meet <1 s overall. |
| Bot SIGTERM / redeploy | Stop new assignments, bound utterance completion/truncation, push final checkpoint and release. One ≤2 s target covers this whole handoff. If commit/capacity misses the deadline, report fallback to the prior checkpoint/`OutcomeUnknown`; do not wait for call end or promise fresh state. |
| Planned worker move/drain | Existing exact export carries accepted cached state, task/mailbox and audio. Bot holds bounded unsent output, resolves owner, obtains a fresh owner-issued token and reattaches. A failed move can return to source with a fresh attachment. Bot process stays alive. |
| Worker crash | Existing control-driven takeover validates the store checkpoint and ADR 0002 envelope. Bot resolves the new epoch and replaces speculative context with its state, even if Python has a higher unacknowledged sequence. No bot restart. Control down delays takeover, not ongoing calls/bot replacement on surviving workers. |

A new bot reconstructs prompt/tools from a matching configuration revision and restores messages. Checkpoint completed user text **before** starting generation if automatic turn restart is required. A helper waits asynchronously for durability; media continues. Lost LLM/TTS work is `OutcomeUnknown` and restarts under a new turn. Speech lost before a recoverable transcript exists requires an explicit repeat request. This limitation needs owner acceptance; durable recordings are outside scope. Tools with external effects need application idempotency/query semantics; transport replacement alone cannot provide them.

## Checkpoints and budgets

Persist bridge schema/config revision, attachment lineage, checkpoint sequence, bot input cursor (SSRC/index), turn/phase and pending user text in working bytes; persist conversation messages/summary in History. Do not persist sockets, credentials, prompt/tool definitions, recordings or codec buffers. A worker-side accepted checkpoint is not durable. Add a narrow built-in observer at checkpoint acknowledgement, carrying the exact captured bridge pair, including settled uncertain commits. Send `checkpointed` only for that pair. Later local state must not receive an earlier write's acknowledgement.

Coalesce replaceable bot pushes in one bounded pending slot to `SaveInterval` (100 ms default). Faster pushes replace unaccepted candidates, get `superseded`, and cause no extra store writes. Accepted state always passes normal admission; history churn shares the existing quota and reserves. Refuse before acceptance with typed capacity/budget outcomes, retain the prior pair, and backpressure Python. Never slow transport snapshots, silently truncate accepted state, or bypass a forced side-effect intent checkpoint.

Use `sessionstore.Store` and `ComponentStore` through the existing checkpoint module. No Redis types, keys or commands enter bridge APIs or the Python protocol. Preserve **6,144 B hot**, **70,000 B/s**, **40,960 B burst**, transaction/component caps and quota across moves. [#214](https://github.com/relaishq/relais/issues/214) records owner acceptance on 2026-10-23 with only 1.3–3.4% full-size headroom; extra bridge metadata/tasks need actual encoded-size and traffic proof. History at 10 Hz is not affordable. Oversize policy runs locally: deterministic oldest-exchange removal, summary update supplied by the app, visible truncation metadata; no automatic summarizer request. Never split a tool/result pair. If the newest exchange alone cannot fit, return an explicit refusal.

## Connections and protocol v1

This is the complete new connection allowlist. Nothing phones home. Dependency installation is an operator action, separate from runtime. Disable automatic model downloads, provider discovery, tracing/exporters and update checks; local paths must supply VAD assets. V1 adds no network exporter or extension client. DNS, when names are configured, queries only those names (A/AAAA); TLS sends configured SNI and certificates, never state. Test denied egress at startup and during recovery.

| Connection | Exact application fields |
| --- | --- |
| Runner → each configured worker, registry WebSocket | TLS identity or Authorization header; `hello(protocol, bot_instance, agent_name, config_revision, capacity)`; `reserve(session_id, epoch, reservation_id, expires_ms)`; `reserved(reservation_id, accepted)`; `assign(session_id, epoch, attach_token, expires_ms)`; `ping/pong(nonce)`. |
| Bot → bootstrap worker, HTTPS owner lookup | Authentication; request `session_id`; reply `owner, epoch, worker_url` from the configured directory. No checkpoint/media/token disclosure here. |
| Bot → owning worker, session WebSocket | Authentication; `attach(protocol, session_id, epoch, bot_instance, attach_token, last_checkpoint_seq)`; `attached(epoch, generation, resume, checkpoint_seq, checkpoint_age_ms, snapshot_age_ms, working, history, outcome_unknown, duplicate_windows, limits)`; every later message is scoped to that socket's epoch/generation. |
| Session binary frames | Input `type=1, input_ssrc:u32, input_seq:u64, rtp_ts:u32, duplicate:u8, opus`; output `type=2, turn:u64, seq:u64, opus`. Integers big-endian; payload consumes remainder. Reject malformed lengths/durations and conflicting sequences. |
| Session JSON frames | `checkpoint(seq, version, input_ssrc, input_seq, working, history)`; `checkpointed(seq)`; `superseded(seq)`; `refused(seq, reason)`; `clear_audio(before_turn)`; `cancel_before(turn)`; `playback_finished(turn)`; `control(id, sequence, name, data)`; `moving(owner, epoch)` advisory; `release(final_checkpoint_seq)`; `ping/pong(nonce)`; `input_gap(first_seq, last_seq)`; `outcome_unknown(turn, reason)`. Bytes use base64; duplicate windows use SSRC/first/last indexes. |
| Worker → existing store | Existing lease/clock and fenced component operations only; same session, owner/epoch, captured bytes/references, quota and acknowledgement metadata. Memory makes no connection; configured store adapter owns its wire format. |
| Optional application providers | None in bridge packages. Existing STT/LLM/TTS/tools remain app-owned connections. Each enabled demo adapter must list endpoint, headers, authentication, model/settings, audio/text/context/tool fields in its own manifest before release. No universal provider-field inventory or provider call is implied here. |

`limits` contains `working_bytes, history_bytes, json_bytes, binary_bytes, input_packets, move_bytes`; `resume` is fresh/planned_move/takeover/bot_restart. Bot input acknowledgement never fabricates durable host progress. Bound JSON to 32 KiB, binary messages to 1,200 B, input outbox to 32 packets and all queues to existing per-session/worker move-memory caps; reserve a control lane. Output backpressures with cancellation. Unknown protocol majors/schema versions refuse; additive optional fields negotiate explicitly. Persisted bridge/config versions must match a tested pool; never fall back to echo.

Emit stable local events `relais.bridge/v1`: `bot_attached`, `bot_detached`, `bot_takeover`, `bot_refused`. Fields: `event_version, event_id, observed_at, session_id, owner_epoch, generation, cause, outcome, duration_ms, checkpoint_age_ms`; nullable fields stay explicit. Durations use local monotonic time; causes/outcomes are bounded enums. No tokens, media, history or provider credentials. Bounded nonblocking local stdout/file delivery counts dropped events; optional exporters cannot gate state. Metrics use bounded labels, never session IDs.

## Ordered implementation slices

1. **Task-path measurement:** keyless synthetic streaming spike above; verify overload, cancellation, DTX pacing, full-size admission and existing timing gates. Publish raw evidence; choose batching/effect before proceeding.
2. **Authenticated attach:** versioned shared Go/Python fixtures, worker registration/lookup, one-use tokens and generation fences. Test bad/expired/replayed/cross-session/epoch tokens, capacity races, stale owners and control-down bot replacement.
3. **Checkpointed loopback:** bridge actor plus minimal asyncio/PyAV client. Test nonblocking Save, rollback/outbox isolation, exact durable acknowledgements, lost replies, fast pushes, overflow and local event schemas. Run both store implementations; preserve outage/fencing behavior.
4. **Recovery:** real bot SIGKILL, hung pipeline and SIGTERM; planned worker move/drain/crash with the same bot PID. Test sequence conflicts, replay, unknown turns, old-socket exclusion and no-capacity. Preserve existing consent/decryption/gap gates; short additions stay below 15 s.
5. **Pipecat adoption:** pinned transport/context helper, offline codec/VAD fixtures, history truncation/config compatibility and interrupted output. Verify transport-plus-setup-only migration with a representative existing bot. Add the five-minute guide and Move/Drain/Kill worker/Kill bot/Redeploy controls.
6. **Acceptance:** owner-decided benchmark order (2026-10-23): lead with “the bot crashes or redeploys and the call doesn't drop” versus Pipecat SmallWebRTC. Second: “the conversation survives an agent crash” versus LiveKit Agents. Publish pinned versions, dispatch/context, caller gaps/first audio, sample count, p95, failures, hardware and raw data. Provider demos need separate authorization; none run here.

## Evidence and conflicts

Inspected ADRs 0002/0004/0006/0008/0010/0012/0013, glossary and standards; `pkg/agent/v2/agent.go`, `pkg/workerapp/{registration,flags,agent}.go`, and mediaworker accepted-event, task, playback and checkpoint modules. This design preserves their actor, fencing, size and recovery limits.

Official pages checked 2026-10-23: [Pipecat SmallWebRTC](https://docs.pipecat.ai/api-reference/server/services/transport/small-webrtc) describes direct peer-to-peer operation; bot-death call loss is an architectural inference to benchmark. [Frames](https://reference-server.pipecat.ai/en/latest/api/pipecat.frames.frames.html) define PCM input/output and interruption frames; [LLMContext](https://reference-server.pipecat.ai/en/latest/api/pipecat.processors.aggregators.llm_context.html) exposes mutable messages/tools. [PyAV installation](https://pyav.org/docs/stable/overview/installation.html) documents wheels with libopus; validate selected wheels. LiveKit documents [approximately 15 s redispatch](https://docs.livekit.io/agents/server/lifecycle/), [10 s default shutdown hooks](https://docs.livekit.io/agents/server/job/), and [up to one hour Cloud deployment drain](https://docs.livekit.io/deploy/agents/managing-deployments/). These do not prove that LiveKit context can only be saved at shutdown; apps can persist earlier. No comparative runtime result is claimed.
